# v0.22 — Homologação e Deploy

## Objetivo
Ambiente reproduzível de staging para validar o sistema antes de qualquer operação com dinheiro real.

## Serviços
- PostgreSQL 16
- Redis 7
- API FastAPI
- Worker
- Nginx

## Subir staging
1. Copie `.env.staging.example` para `.env.staging`.
2. Troque todos os segredos de exemplo.
3. Execute `./scripts/deploy_staging.sh`.
4. Execute `./scripts/smoke_staging.sh`.

O staging usa a porta `8080` por padrão e volumes próprios, separados do Compose de produção.

## Mercado Pago
Use exclusivamente credenciais de teste no staging. O Access Token não deve ser colocado no Flutter nem no repositório. Configure o webhook de teste apontando para um endpoint HTTPS acessível pelo ambiente de homologação.

## Android
O projeto suporta flavors `staging` e `production`. Exemplos:

```bash
flutter run --flavor staging
flutter build apk --flavor staging --release
flutter build appbundle --flavor production --release
```

## Critérios de aceite
- `/health` e `/health/ready` respondem 200.
- Migrações Alembic aplicam sem erro.
- API conecta em PostgreSQL e Redis.
- Worker inicia sem erro.
- Testes automatizados passam.
- Fluxo Pix usa somente sandbox/test credentials.
- Nenhum segredo fica versionado.
- Backup e restauração são testados antes de produção.
