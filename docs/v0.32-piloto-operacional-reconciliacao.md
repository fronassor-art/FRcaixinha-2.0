# FRcaixinha 2.0 — v0.32 Piloto Operacional + Reconciliação

## Objetivo
Executar o piloto com rastreabilidade financeira independente e detectar divergências antes do fechamento.

## Regras
- Nenhum registro financeiro é apagado para corrigir divergência; usar reversão/reconciliação auditável.
- Pagamentos aprovados devem possuir lançamento no Ledger.
- `provider + provider_payment_id` é único.
- `provider + event_id` de Webhook é único.
- Parcelas abertas não podem ter saldo negativo.
- Webhooks pendentes bloqueiam o fechamento até serem processados ou tratados.

## Execução
1. Rodar `scripts/reconcile_v032.py` no ambiente com `PYTHONPATH=backend`.
2. Guardar o JSON gerado como evidência do piloto.
3. Investigar cada `FAIL`.
4. Corrigir por operação reversível/auditável.
5. Rodar novamente até `PASS`.
6. Só então executar fechamento.

A API administrativa também expõe `GET /api/admin/reconciliation/run` e exige autenticação administrativa.

## Mercado Pago
O Mercado Pago recomenda Webhooks para notificações e disponibiliza URL/test credentials para testes antes da produção. A origem da notificação deve ser validada pela assinatura secreta quando aplicável. O sistema deve consultar o pagamento no provedor antes de efetivar a mudança financeira.

## Critério GO
GO somente quando a reconciliação estiver PASS, backup/restauração tiverem sido comprovados, monitoramento estiver ativo, nenhum Webhook estiver pendente e os gates jurídico/regulatórios estiverem aprovados.
