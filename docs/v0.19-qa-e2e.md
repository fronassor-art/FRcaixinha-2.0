# v0.19 — QA, E2E e Concorrência

## Objetivo

A v0.19 fecha o ciclo de qualidade antes da produção. O foco é testar contratos, invariantes financeiros, idempotência e o fluxo completo com serviços reais em ambiente controlado.

## Invariante principal

Uma mesma intenção financeira não pode produzir dois pagamentos no provedor nem dois lançamentos no Ledger. Para isso, as cobranças por contribuição e parcela usam chaves de idempotência determinísticas por recurso, em vez de UUID aleatório.

## Testes automatizados

```bash
cd backend
pip install -r requirements.txt
pytest -q
```

Os testes QA podem ser executados isoladamente:

```bash
pytest -q tests/qa
```

## E2E com serviços

1. Subir o sandbox:

```bash
./scripts/run_sandbox.sh
```

2. Aplicar migrations e seed conforme o README do sandbox.
3. Executar a suíte E2E marcada com `e2e`/`integration`.
4. Confirmar que cada webhook repetido retorna `duplicate=true` ou não reaplica a operação.
5. Confirmar no banco que existe apenas um Payment por `provider/provider_payment_id` e apenas um lançamento financeiro por referência.

## Cenários de aceite

- Cadastro e login.
- Contribuição pendente.
- Criação de Pix de contribuição.
- Repetição concorrente da criação: uma cobrança lógica.
- Aprovação do Pix pelo mock.
- Webhook aprovado.
- Webhook repetido.
- Solicitação de empréstimo.
- Aprovação administrativa.
- Liberação e débito no Ledger.
- Geração mensal de parcelas.
- Parcela em atraso e penalidade diária.
- Pix da parcela.
- Webhook aprovado da parcela.
- Repetição do webhook sem novo pagamento/Ledger.
- Quitação do empréstimo.
- Notificação e relatório.

## Mercado Pago

O sandbox deve usar credenciais de teste. A URL de Webhook de teste deve ser diferente da produção. A integração mantém validação de `x-signature` e consulta do pagamento após a notificação.

## Concorrência

O teste de concorrência deve disparar duas ou mais requisições para o mesmo recurso. O resultado esperado é uma única intenção de cobrança. A idempotência no provedor e as restrições únicas no banco são camadas complementares; nenhuma delas deve ser removida.

## Limitação

A suíte executada automaticamente no pacote não deve usar credenciais produtivas, dinheiro real ou dados pessoais reais.
