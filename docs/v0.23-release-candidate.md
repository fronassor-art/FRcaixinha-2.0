# FRcaixinha 2.0 — v0.23 Release Candidate

## Objetivo

A v0.23 consolida o projeto para uma revisão final antes de produção. Ela não autoriza operação financeira real: o Go/No-Go exige homologação concluída, credenciais de produção protegidas, HTTPS válido, backup restaurado em teste e revisão jurídica/regulatória.

## Checklist técnico

- [x] FastAPI + JWT
- [x] PostgreSQL + Alembic
- [x] Redis + Worker
- [x] Mercado Pago com idempotência e Webhook
- [x] Ledger com referências para evitar lançamentos duplicados
- [x] Empréstimos, parcelas e motor financeiro
- [x] Notificações
- [x] Relatórios/PDF
- [x] Docker/Nginx
- [x] Prometheus/Alertmanager/Grafana
- [x] Backup operacional
- [x] Android com staging/production
- [x] QA automatizado

## Gates obrigatórios antes do Go

1. Executar `scripts/rc_v023.sh` em ambiente limpo.
2. Executar `alembic upgrade head` em PostgreSQL de homologação.
3. Executar o fluxo E2E usando Mercado Pago Sandbox.
4. Confirmar que Webhook inválido não altera o Ledger.
5. Repetir o mesmo Webhook e confirmar idempotência.
6. Simular duas criações concorrentes de Pix e confirmar uma única intenção de pagamento.
7. Fazer backup e restauração em banco separado.
8. Confirmar `/health/ready`, métricas e heartbeat do Worker.
9. Confirmar que nenhum segredo, certificado ou keystore está no repositório.
10. Só então aprovar o Go/No-Go.

## Pontos que permanecem deliberadamente fora do pacote

- Credenciais reais do Mercado Pago.
- Senha real do PostgreSQL/Redis.
- Chave privada TLS.
- Keystore de assinatura Android.
- Dados reais de participantes.

Esses itens devem ser fornecidos somente por secrets/environment seguro no ambiente de implantação.
