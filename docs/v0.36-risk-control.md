# v0.36 — Controle de Caixa e Limites de Risco

A v0.36 adiciona controles server-side para impedir liberações que ultrapassem limites configurados pelo administrador.

## Limites por grupo
- `min_cash_reserve`: saldo mínimo que deve permanecer após a liberação.
- `max_member_exposure`: exposição máxima de principal ativo por participante.
- `max_global_exposure`: exposição máxima de principal ativo da caixinha.
- `max_exposure_ratio`: exposição global máxima como proporção do saldo de caixa.

## Regra de liberação
Antes de liberar um empréstimo APPROVED, a API calcula o cenário pós-liberação. Em PostgreSQL, a linha do grupo é bloqueada com `FOR UPDATE` durante a decisão para evitar que duas liberações concorrentes passem simultaneamente pelos mesmos limites.

## Endpoints administrativos
- `GET /api/admin/risk/groups/{group_id}` — limites e situação atual.
- `PUT /api/admin/risk/groups/{group_id}` — altera limites e registra auditoria.
- `GET /api/admin/risk/preview-release/{loan_id}` — simula a liberação sem executá-la.

## Observações
Os limites são parâmetros operacionais; valores concretos devem ser definidos pelo administrador após análise financeira e jurídica. A API não considera a aprovação do empréstimo como autorização para ignorar os limites: a checagem é feita novamente no servidor no momento da liberação.
