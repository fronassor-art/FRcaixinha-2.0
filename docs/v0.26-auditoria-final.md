# FRcaixinha 2.0 — v0.26 Auditoria Final + Go/No-Go

## Objetivo
A v0.26 consolida os controles de segurança e transforma a preparação de produção em um processo verificável. Ela não deve ser interpretada como autorização automática para operar dinheiro real.

## Controles técnicos fechados
- Cadeia Alembic única terminando em `0010_security_reconciliation`.
- Migration `0006_security_v11` presente para novas instalações.
- Reconciliação `0010` para bancos legados que chegaram a `0009` sem as tabelas de segurança.
- Sessões com JTI persistido, revogação e timeout de inatividade.
- Logout revoga a sessão atual.
- Troca/reset de senha revoga sessões existentes.
- Throttling de login e recuperação de senha.
- Tokens de recuperação são armazenados apenas como hash; o token bruto não é persistido em `Notification`.
- Em produção, Swagger/ReDoc/OpenAPI ficam desabilitados.
- `ALLOWED_HOSTS` e `CORS_ORIGINS` não podem ser curingas em produção.
- Segredos de produção entram por Docker Secrets e `*_FILE`.
- `/metrics` não fica exposto pelo Nginx.
- Prometheus/Grafana/Alertmanager permanecem na rede interna.
- Backup e restore continuam disponíveis para operação controlada.

## Segurança de autenticação
A arquitetura usa Argon2 para senhas, tokens de recuperação aleatórios e de uso único, além de sessões revogáveis. Esses controles são coerentes com as recomendações do OWASP para autenticação, recuperação de senha e gerenciamento de sessões.

## Auditoria de dependências
O pacote mantém versões fixadas em `backend/requirements.txt`. A execução de `pip-audit` é tratada como controle separado porque a ferramenta e o acesso ao índice de pacotes não são garantidos no ambiente de build. O Go-Live exige executar essa auditoria no CI/servidor de release e registrar o resultado.

## Go/No-Go

### GO somente se todos forem verdadeiros
- [ ] `scripts/audit_v026.sh` sem falhas.
- [ ] `preflight_production.sh` aprovado no servidor real.
- [ ] DNS e TLS válidos.
- [ ] Secrets reais configurados, fora do Git e com permissões restritas.
- [ ] Mercado Pago produção configurado e webhook HTTPS validado.
- [ ] SMTP de produção validado, se e-mail estiver habilitado.
- [ ] Migração aplicada e banco verificado.
- [ ] Backup novo criado.
- [ ] Restore testado em ambiente separado.
- [ ] Smoke test aprovado após deploy.
- [ ] Alertmanager com receptor real e teste de alerta realizado.
- [ ] Monitoramento sem portas públicas desnecessárias.
- [ ] Android release assinado e testado.
- [ ] Termos e política de privacidade publicados.
- [ ] Fluxo de custódia dos recursos aprovado juridicamente/regulatoriamente.
- [ ] Política de juros, multas e demais encargos revisada juridicamente.
- [ ] Plano de resposta a incidente e rollback testados.
- [ ] Revisão humana final pelo responsável operacional.

### NO-GO por padrão
O pacote permanece **NO-GO** até que os itens externos acima sejam comprovados. Passar nos testes estáticos não equivale a provar que o ambiente de produção está seguro ou legalmente autorizado.

## Comandos de validação

```bash
./scripts/audit_v026.sh
./scripts/preflight_production.sh
./scripts/smoke_production.sh
./scripts/backup_postgres.sh
```

Para restore, use uma cópia de homologação primeiro:

```bash
CONFIRM_RESTORE=YES ./scripts/restore_postgres.sh backups/ARQUIVO.sql.gz
```
