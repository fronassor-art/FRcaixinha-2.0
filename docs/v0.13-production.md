# v0.13 — Produção e Infraestrutura

## Runtime e serviços

- A imagem usa Python 3.13, executa como usuário não-root e inicia com
  `fastapi run app/main.py --host 0.0.0.0 --port "$PORT"`. Se `PORT` não
  estiver definida, usa 8000.
- Em `APP_ENV=production`, `DATABASE_URL` precisa usar
  `postgresql+psycopg://`; SQLite é reservado para desenvolvimento/testes.
- `DATABASE_URL` e `JWT_SECRET` são obrigatórios. Os valores literais
  `change_me` e `CHANGE_ME_DB_PASSWORD` usados nos exemplos são recusados
  em production quando aplicados a esses segredos/configuração.
- `ALLOWED_HOSTS` e `CORS_ORIGINS` precisam ser explícitos em production.
  Ainda não há domínio público escolhido; os valores do exemplo ficam em
  branco até que os hosts reais sejam definidos.
- TLS termina fora do processo FastAPI, em ingress/proxy HTTPS. O backend
  não provisiona domínio ou certificado.
- Alembic não roda no startup web. Execute uma única etapa
  `alembic upgrade head` antes de iniciar ou escalar as réplicas.
- O processo web é o comando do container. O worker é separado:
  `python -m app.worker.main`; ele executa tarefas agendadas e depende de
  Redis acessível para os locks distribuídos. Redis não é obrigatório no
  startup do processo web. Rate limit e métricas do web usam Redis como
  melhor esforço; se indisponível, as operações web continuam.
- O storage de evidências é filesystem POSIX local, configurável por
  `WORKFLOW_EVIDENCE_STORAGE_ROOT`. Web e worker precisam do mesmo volume
  persistente: o worker verifica arquivos enviados pelo web. Upload/download
  detectam falhas de escrita/leitura; o worker registra falhas de verificação.
- `MERCADO_PAGO_ACCESS_TOKEN` e `MERCADO_PAGO_WEBHOOK_SECRET` não são
  obrigatórios para subir o web process. São requisitos operacionais para
  habilitar criação/consulta PIX e aceitar webhooks assinados.
- `GET /health` é liveness. `GET /health/ready` verifica o banco com
  `SELECT 1`; nenhum verifica Redis ou storage.
- Logs JSON são enviados a stdout. O nível atual é INFO.

## Production topology

`docker-compose.prod.yml` defines two processes from the same backend image:

- `web` runs the Dockerfile command and listens on `PORT` (default 8000).
- `worker` runs `python -m app.worker.main`; it has no HTTP health endpoint.
- PostgreSQL and Redis are external. The compose file mounts `database_url`,
  `jwt_secret`, and `redis_url` file secrets; the worker requires all three.
  The web requires only the database and JWT secrets. Its Redis rate limit and
  metrics paths are best-effort. Both processes receive production `APP_ENV`,
  `ALLOWED_HOSTS`, and `CORS_ORIGINS`.
- Both processes mount the same named `workflow_evidence` volume at
  `/var/lib/frcaixinha/workflow-evidence`. The web stores uploaded evidence;
  the worker verifies it. For separate services/hosts, provide shared
  persistent POSIX storage mounted at the same path.
- The example does not contain a public host. Fill `ALLOWED_HOSTS` and
  `CORS_ORIGINS` with real values before starting production.

Mercado Pago credentials are web-only and optional for process startup. Set
`MERCADO_PAGO_ACCESS_TOKEN` to enable provider create/query operations and
`MERCADO_PAGO_WEBHOOK_SECRET` to accept signed webhooks. SMTP and payout
encryption credentials are feature-specific. They are not mounted as
mandatory Compose secrets; inject them only when enabling those features.
Settings supports `*_FILE` for database, JWT, Redis, Mercado Pago, SMTP, and
payout encryption secrets; optional secret files must be mounted by the chosen
runtime.

## Release sequence

1. Provide external PostgreSQL and Redis, the three Compose secret files under
   `./secrets/`, and the untracked `.env.production` based on the example.
2. Build the image, then run the migration once before starting any web or
   worker replicas:

   `docker compose --env-file .env.production -f docker-compose.prod.yml run --rm --no-deps web alembic upgrade head`

3. Start `web` and `worker` only after the migration succeeds. The web and
   worker commands do not run migrations, so scaling them does not start
   concurrent Alembic upgrades.
4. Terminate HTTPS at the platform ingress/reverse proxy. Point the ingress at
   the web container port from `PORT` (default 8000); the compose file does not
   publish a host port or provision TLS.
5. Configure the Mercado Pago webhook URL externally over HTTPS only if PIX is
   enabled. Verify `GET /health` and `GET /health/ready`; the latter checks
   PostgreSQL only. Configure backups, monitoring, and restoration separately.

## Segurança
- Não publique PostgreSQL/Redis na internet.
- Não coloque Access Token do Mercado Pago no Flutter.
- Use HTTPS no proxy reverso.
- Guarde `.env` fora do repositório.
- Faça restauração de backup em ambiente de teste periodicamente.
- Para múltiplas réplicas, prefira um processo por container e faça a replicação no orquestrador.

## Observação
`docker-compose.yml` is the local stack and includes PostgreSQL, Redis, web,
worker, and volumes. The production compose describes web and worker while
leaving PostgreSQL, Redis, ingress, and TLS external. No cloud provider or
public host is selected here.
