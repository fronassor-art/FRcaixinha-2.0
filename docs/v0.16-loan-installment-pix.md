# v0.16 — Pix de parcelas de empréstimos

Esta versão fecha o ciclo de pagamento de parcelas: cobrança Pix individual, idempotência, webhook, baixa da parcela, Ledger e notificação.

> **Nota de atualização:** este documento registra o fluxo inicial da v0.16 e deve ser lido como histórico. O fluxo evoluiu: o estado atual cria cobranças pela Mercado Pago Orders API (`POST /v1/orders`) e consulta a Order antes da confirmação financeira. A confirmação atual não deve ser descrita apenas como `approved`: o estado legado `approved` continua aceito, e Orders API também exige `processed` com `status_detail == accredited`; `processed` sem `accredited` não cria settlement.
>
> Para parcela de empréstimo, existe uma tentativa Pix versionada e reservada localmente antes da chamada ao provedor, com idempotência, validade e snapshot financeiro. O registro persiste `provider_order_id` e, quando retornados, os dados do QR (`qr_code`, `qr_code_base64`) e `ticket_url`. O webhook reconsulta a Order antes de confirmar financeiramente. Settlement e Ledger têm proteção idempotente.
>
> Checkpoint de referência do estado atual: SHA `221226b3f9b0c93517721398de3cc85b2d565a2a`.

## Endpoints
- `POST /api/loan-installments/{id}/pix`
- `GET /api/loan-installments/{id}/payment`

## Fluxo
1. O membro solicita o Pix de uma parcela aberta.
2. O backend cria ou reutiliza a cobrança pendente.
3. O Access Token do Mercado Pago permanece somente no backend.
4. O webhook valida a assinatura e consulta o pagamento atualizado. (Descrição do fluxo inicial; veja a nota de atualização acima para o estado atual.)
5. No fluxo inicial, `approved` baixava a parcela e lançava o crédito no Ledger uma única vez.
6. O membro recebe uma notificação.
