# FRcaixinha 2.0 — v0.22 Production Ready

## Objetivo

Preparar o projeto para uma operação de produção real sem colocar credenciais, chaves de assinatura ou certificados no repositório.

## Entregas

- Compose dedicado para produção.
- PostgreSQL e Redis em rede privada.
- Nginx com HTTPS/TLS e redirecionamento HTTP→HTTPS.
- Preflight obrigatório antes do deploy.
- Secrets fora da imagem e fora do Git.
- Migração Alembic executada antes de subir a nova API.
- Script de deploy reproduzível.
- Política de arquivos sensíveis no `.gitignore.production`.
- Checklist de domínio, DNS, TLS, Mercado Pago, SMTP, backup e monitoramento.

## Antes de produção

1. Criar DNS para o domínio da API.
2. Emitir certificado TLS válido e colocar os arquivos em `ops/tls/`.
3. Criar `.env.production` fora do Git.
4. Criar `ops/secrets/db_password.txt` com permissão 600.
5. Definir `REDIS_PASSWORD` no ambiente de execução.
6. Configurar credenciais de produção do Mercado Pago somente no servidor.
7. Configurar SMTP real.
8. Testar backup e restauração.
9. Executar `scripts/preflight_production.sh`.
10. Executar `scripts/deploy_production.sh`.
11. Validar `/health` e `/health/ready`.
12. Testar Webhook HTTPS do Mercado Pago em sandbox antes da troca para produção.
13. Fazer smoke test financeiro com valores de teste.

## Segredos

Não coloque Access Token do Mercado Pago, senha do banco, senha SMTP, JWT secret, certificados TLS ou keystore Android no Git. O Docker recomenda mecanismos de secrets em vez de gravar dados sensíveis em `ARG`/`ENV` durante o build.

## Android

A versão de produção deve ser assinada com uma chave sob controle do proprietário do aplicativo. Para Google Play, o formato recomendado é AAB; APK é útil para distribuição direta e testes.

## Rollback

Antes de cada deploy, gerar backup do banco. Em caso de falha, restaurar o último backup compatível e retornar a imagem anterior. Não executar rollback de schema sem verificar compatibilidade das migrations.

## Go/No-Go

**GO somente quando:** HTTPS, backups restauráveis, secrets configurados, Mercado Pago validado, smoke test aprovado, logs/monitoramento disponíveis e revisão jurídica/regulatória concluída.
